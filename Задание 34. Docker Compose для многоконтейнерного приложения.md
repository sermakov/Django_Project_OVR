## Задача 1: Введение в Docker Compose

### 1.1. Что такое Docker Compose?

**Docker Compose** — это инструмент для определения и запуска многоконтейнерных Docker-приложений. Вместо того чтобы запускать каждый контейнер вручную с длинными командами `docker run`, вы описываете все сервисы в одном YAML-файле и управляете ими одной командой.

**Когда нужен Docker Compose:**

- Приложение состоит из нескольких компонентов (веб-сервер, база данных, кэш, очередь задач).
- Нужно координировать запуск контейнеров (например, база данных должна запуститься раньше приложения).
- Нужно легко воспроизводить окружение для разработки, тестирования и деплоя.

### 1.2. Основные понятия Docker Compose

- **Сервис (service)** — описание одного контейнера: какой образ использовать, какие порты открыть, какие переменные передать.
- **Том (volume)** — механизм для сохранения данных контейнера. Данные в контейнере без тома теряются при перезапуске.
- **Сеть (network)** — виртуальная сеть для связи контейнеров. Docker Compose создаёт сеть автоматически; контейнеры обращаются друг к другу по имени сервиса.

### 1.3. Архитектура нашего приложения

В этом занятии мы развернём три сервиса:

```
┌─────────────────────────────────────────┐
│            Docker Compose               │
│                                         │
│  ┌──────────┐  ┌──────────┐  ┌───────┐ │
│  │  Django   │──│PostgreSQL│  │ Redis │ │
│  │  (web)    │  │  (db)    │  │(cache)│ │
│  │ :8000     │  │ :5432    │  │ :6379 │ │
│  └──────────┘  └──────────┘  └───────┘ │
│       │              │            │     │
│       ▼              ▼            ▼     │
│   volumes:       pgdata:      redis:    │
│   static,media   данные БД    данные    │
└─────────────────────────────────────────┘
```

## Задача 2: Создание файла docker-compose.yml

### 2.1. Создание файла

Создайте файл `docker-compose.yml` в каталоге `project_event_manager` (рядом с `Dockerfile` и `manage.py`):

```yaml
version: '3.9'

services:
  # === Сервис базы данных PostgreSQL ===
  db:
    image: postgres:16-alpine
    container_name: event_manager_db
    restart: unless-stopped
    environment:
      POSTGRES_DB: event_manager_db
      POSTGRES_USER: event_user
      POSTGRES_PASSWORD: event_password
    volumes:
      - pgdata:/var/lib/postgresql/data
    ports:
      - "5432:5432"
    healthcheck:
      test: ["CMD-SHELL", "pg_isready -U event_user -d event_manager_db"]
      interval: 5s
      timeout: 5s
      retries: 5

  # === Сервис кэширования Redis ===
  redis:
    image: redis:7-alpine
    container_name: event_manager_redis
    restart: unless-stopped
    ports:
      - "6379:6379"
    volumes:
      - redisdata:/data
    healthcheck:
      test: ["CMD", "redis-cli", "ping"]
      interval: 5s
      timeout: 5s
      retries: 5

  # === Сервис Django-приложения ===
  web:
    build:
      context: .
      dockerfile: Dockerfile
    container_name: event_manager_web
    restart: unless-stopped
    command: >
      sh -c "python manage.py migrate &&
             python manage.py collectstatic --noinput &&
             gunicorn event_manager.wsgi:application --bind 0.0.0.0:8000"
    ports:
      - "8000:8000"
    env_file:
      - .env
    volumes:
      - static_data:/app/staticfiles
      - media_data:/app/media
    depends_on:
      db:
        condition: service_healthy
      redis:
        condition: service_healthy

# === Именованные тома ===
volumes:
  pgdata:
  redisdata:
  static_data:
  media_data:
```

### 2.2. Разбор структуры docker-compose.yml

| Секция | Описание |
|---|---|
| `version` | Версия формата Compose-файла. `3.9` поддерживает все современные возможности. |
| `services` | Описание всех контейнеров (сервисов) приложения. |
| `image` | Готовый образ из Docker Hub (для `db` и `redis`). |
| `build` | Инструкция для сборки образа из Dockerfile (для `web`). |
| `environment` | Переменные окружения, передаваемые в контейнер. |
| `env_file` | Файл с переменными окружения. |
| `volumes` | Привязка именованных томов к директориям контейнера. |
| `ports` | Проброс портов: `хост:контейнер`. |
| `depends_on` | Порядок запуска: `web` ждёт, пока `db` и `redis` будут здоровы. |
| `healthcheck` | Проверка состояния сервиса. |
| `restart` | Политика перезапуска: `unless-stopped` — перезапускать, если не остановлен вручную. |

## Задача 3: Настройка сервиса PostgreSQL

### 3.1. Почему PostgreSQL вместо SQLite?

SQLite хорош для разработки, но имеет ограничения:

- Не поддерживает одновременные записи от нескольких процессов.
- Не подходит для работы в контейнерах (файл БД теряется при пересоздании контейнера).
- Не масштабируется.

PostgreSQL — промышленная СУБД, которая решает все эти проблемы.

### 3.2. Проверка работы PostgreSQL

После запуска (это мы сделаем позже в задаче 6) можно подключиться к базе данных:

```bash
# Подключение через psql внутри контейнера
docker exec -it event_manager_db psql -U event_user -d event_manager_db
```

Полезные команды psql:

```sql
-- Список таблиц
\dt

-- Список баз данных
\l

-- Выход
\q
```

## Задача 4: Настройка сервиса Redis

### 4.1. Зачем нужен Redis?

**Redis** — хранилище данных в оперативной памяти. В нашем проекте Redis используется как:

- **Кэш-бэкенд** — хранение результатов частых запросов для ускорения работы.
- **Бэкенд для сессий** — хранение пользовательских сессий.
- В будущем может использоваться как **брокер задач** для Celery.

### 4.2. Проверка работы Redis

```bash
# Подключение к Redis внутри контейнера
docker exec -it event_manager_redis redis-cli

# Проверка связи
PING
# Ожидаемый ответ: PONG

# Установить и получить значение
SET hello "world"
GET hello

# Выход
EXIT
```

## Задача 5: Адаптация Django-проекта для работы с PostgreSQL и Redis

### 5.1. Обновление файла .env

Откройте файл `.env` в каталоге `project_event_manager` и приведите его к следующему виду:

```env
DEBUG=True
SECRET_KEY='django-insecure-bzxome@us)b+2vua$(sqk!yxm5q!#twuc#vp&h=mqlw5^#(yyp'
ALLOWED_HOSTS=127.0.0.1,localhost

# Настройки PostgreSQL
DB_ENGINE=django.db.backends.postgresql
DB_NAME=event_manager_db
DB_USER=event_user
DB_PASSWORD=event_password
DB_HOST=db
DB_PORT=5432

# Настройки Redis
REDIS_URL=redis://redis:6379/0
```

**Обратите внимание:** В поле `DB_HOST` указано `db` — это имя сервиса из `docker-compose.yml`. Docker Compose автоматически создаёт DNS-запись, по которой контейнеры находят друг друга по имени.

### 5.2. Обновление settings.py — подключение PostgreSQL

Откройте файл `event_manager/settings.py` и замените секцию `DATABASES`:

```python
# Database
# https://docs.djangoproject.com/en/5.1/ref/settings/#databases

DATABASES = {
    'default': {
        'ENGINE': env('DB_ENGINE', default='django.db.backends.sqlite3'),
        'NAME': env('DB_NAME', default=BASE_DIR / 'db.sqlite3'),
        'USER': env('DB_USER', default=''),
        'PASSWORD': env('DB_PASSWORD', default=''),
        'HOST': env('DB_HOST', default=''),
        'PORT': env('DB_PORT', default=''),
    }
}
```

**Пояснение:** Конфигурация гибкая — если переменные окружения не заданы, используется SQLite (для локальной разработки без Docker). Если заданы — PostgreSQL (в контейнере).

### 5.3. Обновление settings.py — подключение Redis

Добавьте в конец файла `event_manager/settings.py` настройку кэширования:

```python
# Cache
# https://docs.djangoproject.com/en/5.1/topics/cache/

CACHES = {
    'default': {
        'BACKEND': 'django_redis.cache.RedisCache',
        'LOCATION': env('REDIS_URL', default='redis://127.0.0.1:6379/0'),
        'OPTIONS': {
            'CLIENT_CLASS': 'django_redis.client.DefaultClient',
        }
    }
}

# Хранение сессий в Redis
SESSION_ENGINE = 'django.contrib.sessions.backends.cache'
SESSION_CACHE_ALIAS = 'default'
```

### 5.4. Обновление ALLOWED_HOSTS

Также обновите секцию `ALLOWED_HOSTS` в `settings.py` для чтения из переменной окружения:

```python
ALLOWED_HOSTS = env('ALLOWED_HOSTS', default='127.0.0.1,localhost').split(',')
```

## Задача 6: Запуск многоконтейнерного приложения

### 6.1. Сборка и запуск

Откройте терминал в каталоге `project_event_manager` и выполните:

```bash
# Сборка образов и запуск контейнеров
docker compose up --build -d
```

**Разбор команды:**
- `docker compose up` — создаёт и запускает все сервисы из `docker-compose.yml`.
- `--build` — принудительно пересобирает образы (полезно после изменения кода).
- `-d` — запуск в фоновом режиме.

### 6.2. Проверка статуса сервисов

```bash
docker compose ps
```

Ожидаемый вывод:
```
NAME                   IMAGE                  STATUS                   PORTS
event_manager_db       postgres:16-alpine     Up (healthy)             0.0.0.0:5432->5432/tcp
event_manager_redis    redis:7-alpine         Up (healthy)             0.0.0.0:6379->6379/tcp
event_manager_web      project-web            Up                       0.0.0.0:8000->8000/tcp
```

### 6.3. Проверка работы приложения

1. Откройте браузер: [http://localhost:8000](http://localhost:8000)
2. Убедитесь, что главная страница загружается.

### 6.4. Создание суперпользователя

```bash
docker compose exec web python manage.py createsuperuser
```

Введите имя пользователя, email и пароль. Затем перейдите в админ-панель: [http://localhost:8000/admin/](http://localhost:8000/admin/)

### 6.5. Просмотр логов

```bash
# Логи всех сервисов
docker compose logs

# Логи конкретного сервиса
docker compose logs web

# Следить за логами в реальном времени
docker compose logs -f web
```

## Задача 7: Управление контейнерами через Docker Compose

### 7.1. Основные команды Docker Compose

```bash
# Остановить все сервисы (контейнеры сохраняются)
docker compose stop

# Запустить ранее остановленные сервисы
docker compose start

# Перезапустить сервисы
docker compose restart

# Остановить и удалить контейнеры (данные в томах сохраняются!)
docker compose down

# Остановить, удалить контейнеры И тома (ПОТЕРЯ ДАННЫХ!)
docker compose down -v
```

### 7.2. Пересборка после изменений

При изменении кода Python:

```bash
# Пересобрать и перезапустить только сервис web
docker compose up --build -d web
```

При изменении `docker-compose.yml`:

```bash
# Пересоздать все сервисы
docker compose up --build -d
```

### 7.3. Масштабирование (дополнительно)

Docker Compose позволяет запустить несколько экземпляров сервиса:

```bash
# Запустить 3 экземпляра web-сервиса (потребуется балансировщик, например nginx)
docker compose up -d --scale web=3
```

**Примечание:** Для масштабирования необходимо убрать фиксированное имя контейнера (`container_name`) и фиксированный порт из конфигурации сервиса `web`.

## Задача 8: Настройка томов для персистентного хранения данных

### 8.1. Зачем нужны тома?

По умолчанию все данные внутри контейнера **теряются** при его удалении. Тома (volumes) позволяют сохранять данные между пересозданиями контейнеров.

В нашем `docker-compose.yml` мы используем 4 тома:

| Том | Назначение |
|---|---|
| `pgdata` | Данные PostgreSQL (таблицы, индексы) |
| `redisdata` | Данные Redis (кэш, сессии) |
| `static_data` | Статические файлы Django (CSS, JS, изображения) |
| `media_data` | Загруженные пользователями файлы (аватары, документы) |

### 8.2. Просмотр томов

```bash
# Список всех томов
docker volume ls

# Подробная информация о томе
docker volume inspect project_event_manager_pgdata
```

### 8.3. Резервное копирование базы данных

```bash
# Создать дамп базы данных
docker compose exec db pg_dump -U event_user event_manager_db > backup.sql

# Восстановить из дампа
cat backup.sql | docker compose exec -T db psql -U event_user event_manager_db
```
