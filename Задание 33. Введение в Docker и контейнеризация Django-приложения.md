## Задача 1: Введение в контейнеризацию и Docker

### 1.1. Что такое контейнеризация?

**Контейнеризация** — это технология упаковки приложения вместе со всеми его зависимостями (библиотеки, файлы конфигурации, системные утилиты) в единый изолированный контейнер. Контейнер запускается одинаково на любой машине, где установлен Docker.

**Преимущества контейнеризации:**

- **Изоляция**: приложение и его зависимости изолированы от хостовой системы и других приложений.
- **Переносимость**: контейнер работает одинаково на машине разработчика, в CI/CD и на сервере.
- **Воспроизводимость**: окружение описано в виде кода (Dockerfile), что исключает «работает у меня на компьютере».
- **Лёгкость**: контейнеры используют ядро хостовой ОС и потребляют значительно меньше ресурсов, чем виртуальные машины.

### 1.2. Docker: основные понятия

- **Docker Engine** — движок, который запускает и управляет контейнерами.
- **Образ (Image)** — шаблон (набор слоёв) для создания контейнера. Образ неизменяем.
- **Контейнер (Container)** — работающий экземпляр образа. Контейнер можно запускать, останавливать и удалять.
- **Dockerfile** — текстовый файл с инструкциями для сборки образа.
- **Docker Hub** — публичный реестр образов (аналог GitHub для Docker-образов).

### 1.3. Чем контейнер отличается от виртуальной машины?

| Характеристика | Виртуальная машина | Контейнер |
|---|---|---|
| Изоляция | Полная (своё ядро ОС) | Уровень процессов (общее ядро) |
| Размер | Гигабайты | Мегабайты |
| Время запуска | Минуты | Секунды |
| Производительность | Ниже (гипервизор) | Близка к нативной |
| Ресурсоёмкость | Высокая | Низкая |

## Задача 2: Установка Docker

### 2.1. Установка Docker на Windows

1. Перейдите на официальный сайт: [https://www.docker.com/products/docker-desktop/](https://www.docker.com/products/docker-desktop/)
2. Скачайте **Docker Desktop** для Windows.
3. Запустите установщик и следуйте инструкциям.
4. После установки перезагрузите компьютер.
5. Запустите Docker Desktop из меню «Пуск».

**Важно:** Docker Desktop для Windows требует включённого WSL 2 (Windows Subsystem for Linux). Если при первом запуске Docker сообщит об этом, выполните в PowerShell от администратора:

```powershell
wsl --install
```

Затем перезагрузите компьютер и снова запустите Docker Desktop.

### 2.2. Установка Docker на macOS

1. Перейдите на сайт [https://www.docker.com/products/docker-desktop/](https://www.docker.com/products/docker-desktop/)
2. Скачайте Docker Desktop для macOS (версия для Intel или Apple Silicon).
3. Откройте `.dmg` файл и перетащите Docker в папку «Applications».
4. Запустите Docker из Launchpad.

### 2.3. Установка Docker на Linux (Ubuntu)

Выполните команды в терминале:

```bash
# Обновление пакетов
sudo apt-get update

# Установка зависимостей
sudo apt-get install -y ca-certificates curl gnupg

# Добавление GPG-ключа Docker
sudo install -m 0755 -d /etc/apt/keyrings
curl -fsSL https://download.docker.com/linux/ubuntu/gpg | sudo gpg --dearmor -o /etc/apt/keyrings/docker.gpg
sudo chmod a+r /etc/apt/keyrings/docker.gpg

# Добавление репозитория Docker
echo \
  "deb [arch=$(dpkg --print-architecture) signed-by=/etc/apt/keyrings/docker.gpg] https://download.docker.com/linux/ubuntu \
  $(. /etc/os-release && echo "$VERSION_CODENAME") stable" | \
  sudo tee /etc/apt/sources.list.d/docker.list > /dev/null

# Установка Docker
sudo apt-get update
sudo apt-get install -y docker-ce docker-ce-cli containerd.io docker-buildx-plugin docker-compose-plugin

# Добавление пользователя в группу docker (чтобы не писать sudo)
sudo usermod -aG docker $USER
```

После выполнения команд **перезайдите в терминал** (или перезагрузите компьютер).

### 2.4. Проверка установки

Выполните в терминале:

```bash
docker --version
```

Ожидаемый вывод (версия может отличаться):
```
Docker version 27.x.x, build xxxxxxx
```

Запустите тестовый контейнер:

```bash
docker run hello-world
```

Если вы увидите сообщение «Hello from Docker!», установка прошла успешно.

## Задача 3: Изучение основных команд Docker

### 3.1. Работа с образами

```bash
# Скачать образ из Docker Hub
docker pull python:3.12-slim

# Просмотреть список скачанных образов
docker images

# Удалить образ
docker rmi python:3.12-slim
```

### 3.2. Работа с контейнерами

```bash
# Запустить контейнер (интерактивный режим)
docker run -it python:3.12-slim bash

# Выйти из интерактивного контейнера
exit

# Просмотреть запущенные контейнеры
docker ps

# Просмотреть все контейнеры (включая остановленные)
docker ps -a

# Остановить контейнер
docker stop <CONTAINER_ID>

# Удалить контейнер
docker rm <CONTAINER_ID>

# Удалить все остановленные контейнеры
docker container prune
```

### 3.3. Практическое упражнение

1. Скачайте образ `python:3.12-slim`:
   ```bash
   docker pull python:3.12-slim
   ```

2. Запустите интерактивный контейнер с Python:
   ```bash
   docker run -it python:3.12-slim python
   ```

3. В интерпретаторе Python внутри контейнера выполните:
   ```python
   import sys
   print(f"Python {sys.version}")
   print("Привет из Docker-контейнера!")
   exit()
   ```

4. Убедитесь, что контейнер остановился:
   ```bash
   docker ps -a
   ```

**Обратите внимание:** мы добавили `gunicorn==22.0.0` — это продакшн-сервер для Python-приложений. Встроенный `manage.py runserver` не подходит для использования в контейнерах, так как он однопоточный и не предназначен для работы под нагрузкой.

### 4.2. Создание файла .dockerignore

Создайте файл `.dockerignore` в каталоге `project_event_manager` (рядом с `manage.py`):

```
__pycache__
*.pyc
*.pyo
*.mo
*.db
*.sqlite3
.env
.venv
env/
venv/
.git
.gitignore
docker-compose*.yml
Dockerfile
*.md
.idea
.vscode
media/
staticfiles/
*.log
```

**Пояснение:** Файл `.dockerignore` работает аналогично `.gitignore` — он указывает Docker, какие файлы и папки **не нужно** копировать в образ при сборке. Это уменьшает размер образа и ускоряет сборку.

## Задача 5: Написание Dockerfile

### 5.1. Создание Dockerfile

Создайте файл `Dockerfile` (без расширения) в каталоге `project_event_manager`:

```dockerfile
# Базовый образ: легковесная версия Python 3.12
FROM python:3.12-slim

# Устанавливаем переменные окружения
# PYTHONDONTWRITEBYTECODE — не создавать .pyc файлы
# PYTHONUNBUFFERED — не буферизировать вывод (логи сразу видны)
ENV PYTHONDONTWRITEBYTECODE=1
ENV PYTHONUNBUFFERED=1

# Устанавливаем рабочую директорию внутри контейнера
WORKDIR /app

# Устанавливаем системные зависимости
# gcc и python3-dev нужны для компиляции некоторых Python-пакетов
RUN apt-get update && apt-get install -y --no-install-recommends \
    gcc \
    python3-dev \
    libpq-dev \
    && rm -rf /var/lib/apt/lists/*

# Копируем файл зависимостей и устанавливаем их
# Этот шаг кэшируется Docker — если requirements.txt не изменился,
# зависимости не будут переустанавливаться при повторной сборке
COPY requirements.txt .
RUN pip install --no-cache-dir -r requirements.txt

# Копируем весь проект в контейнер
COPY . .

# Собираем статические файлы
RUN python manage.py collectstatic --noinput

# Открываем порт 8000
EXPOSE 8000

# Команда запуска: gunicorn на порту 8000
CMD ["gunicorn", "event_manager.wsgi:application", "--bind", "0.0.0.0:8000"]
```

### 5.2. Разбор Dockerfile по инструкциям

| Инструкция | Описание |
|---|---|
| `FROM` | Указывает базовый образ. Мы используем `python:3.12-slim` — минимальный образ с Python. |
| `ENV` | Устанавливает переменные окружения внутри контейнера. |
| `WORKDIR` | Устанавливает рабочую директорию. Все последующие команды выполняются в ней. |
| `RUN` | Выполняет команду при сборке образа (устанавливает пакеты, выполняет скрипты). |
| `COPY` | Копирует файлы с хост-машины в образ. |
| `EXPOSE` | Документирует, какой порт использует приложение (не публикует его!). |
| `CMD` | Команда, которая выполняется при запуске контейнера. |

### 5.3. Почему мы копируем requirements.txt отдельно?

Docker использует **послойное кэширование**: если содержимое слоя не изменилось, Docker берёт его из кэша. Разделяя копирование `requirements.txt` и остального кода, мы получаем:

1. Если изменился только код Python (но не зависимости) — Docker переиспользует слой с установленными пакетами.
2. Это **значительно ускоряет повторные сборки**.

## Задача 6: Сборка Docker-образа

### 6.1. Сборка образа

Откройте терминал, перейдите в каталог `project_event_manager` (где лежит Dockerfile) и выполните:

```bash
docker build -t event-manager:latest .
```

**Разбор команды:**
- `docker build` — команда сборки образа.
- `-t event-manager:latest` — задаёт имя (tag) образа: `event-manager` с тегом `latest`.
- `.` — контекст сборки (текущая директория).

**Ожидаемый процесс:**

```
[+] Building 45.2s (12/12) FINISHED
 => [1/7] FROM python:3.12-slim
 => [2/7] WORKDIR /app
 => [3/7] RUN apt-get update && apt-get install -y ...
 => [4/7] COPY requirements.txt .
 => [5/7] RUN pip install --no-cache-dir -r requirements.txt
 => [6/7] COPY . .
 => [7/7] RUN python manage.py collectstatic --noinput
 => exporting to image
 => => naming to docker.io/library/event-manager:latest
```

### 6.2. Проверка созданного образа

```bash
docker images
```

Ожидаемый вывод:
```
REPOSITORY       TAG       IMAGE ID       CREATED          SIZE
event-manager    latest    a1b2c3d4e5f6   5 seconds ago    ~350MB
```

## Задача 7: Запуск контейнера с Django-приложением

### 7.1. Запуск контейнера

```bash
docker run -d -p 8000:8000 --name my-django-app event-manager:latest
```

**Разбор флагов:**
- `-d` — запуск в фоновом режиме (detached).
- `-p 8000:8000` — пробрасываем порт: порт 8000 хоста → порт 8000 контейнера.
- `--name my-django-app` — задаём имя контейнера.
- `event-manager:latest` — имя образа.

### 7.2. Проверка работы

1. Убедитесь, что контейнер запущен:
   ```bash
   docker ps
   ```

   Ожидаемый вывод:
   ```
   CONTAINER ID   IMAGE                  COMMAND                  STATUS          PORTS                    NAMES
   abc123def456   event-manager:latest   "gunicorn event_mana…"   Up 10 seconds   0.0.0.0:8000->8000/tcp   my-django-app
   ```

2. Откройте браузер и перейдите по адресу: [http://localhost:8000](http://localhost:8000)

   Вы должны увидеть главную страницу проекта **Event Manager**.

### 7.3. Передача переменных окружения

Для корректной работы приложения необходимо передать переменные из `.env` файла. Остановите текущий контейнер и запустите с переменными окружения:

```bash
# Остановим и удалим контейнер
docker stop my-django-app
docker rm my-django-app

# Запустим с переменными окружения
docker run -d -p 8000:8000 \
  --name my-django-app \
  -e DEBUG=True \
  -e SECRET_KEY='django-insecure-bzxome@us)b+2vua$(sqk!yxm5q!#twuc#vp&h=mqlw5^#(yyp' \
  -e ALLOWED_HOSTS='127.0.0.1,localhost' \
  event-manager:latest
```

**Можно также передать все переменные из файла:**

```bash
docker run -d -p 8000:8000 \
  --name my-django-app \
  --env-file .env \
  event-manager:latest
```

## Задача 8: Работа с контейнером: логи, остановка, удаление

### 8.1. Просмотр логов

```bash
# Просмотр всех логов контейнера
docker logs my-django-app

# Следить за логами в реальном времени (как tail -f)
docker logs -f my-django-app
```

Для выхода из режима слежения нажмите `Ctrl + C`.

### 8.2. Выполнение команд внутри запущенного контейнера

```bash
# Открыть оболочку bash внутри контейнера
docker exec -it my-django-app bash

# Внутри контейнера можно выполнять команды Django
python manage.py showmigrations
python manage.py createsuperuser

# Выход из контейнера
exit
```

### 8.3. Остановка и удаление контейнера

```bash
# Остановить контейнер
docker stop my-django-app

# Удалить контейнер
docker rm my-django-app

# Остановить и удалить одной командой
docker rm -f my-django-app
```

### 8.4. Очистка неиспользуемых ресурсов

```bash
# Удалить все остановленные контейнеры
docker container prune

# Удалить все неиспользуемые образы
docker image prune

# Полная очистка (контейнеры, образы, тома, сети)
docker system prune -a
```

**Внимание:** Команда `docker system prune -a` удалит **все** неиспользуемые ресурсы. Используйте с осторожностью.
